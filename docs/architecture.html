System Architecture

Factory Inventory Management System

A three-tier demo application: a Vue 3 single-page app talks over HTTP to a Python FastAPI service, which serves static JSON fixtures held in process memory. There is no database and no persistence layer — the entire dataset is loaded once at import time.

System Architecture

Two independently started processes. The browser loads the SPA from Vite, then makes cross-origin XHR calls directly to FastAPI — there is no proxy, so the API origin is hardcoded in the client and CORS is opened up on the server.

Data Flow

The filter bar is the spine of the application. Filter state lives in one module-level singleton, so changing a filter in the header re-fetches data for whichever view is mounted — the state is shared, but each view owns its own fetch.

  1. Filter state is a module singleton
    useFilters.js declares selectedPeriod, selectedLocation, selectedCategory and selectedStatus as ref()s outside the composable function. Every caller gets the same four refs, so FilterBar and all views share one source of truth without a store library.
  2. Views watch and re-fetch
    Each view calls getCurrentFilters() to build a plain object, then hands it to the matching api.* method. The period value is passed through as month — it accepts either YYYY-MM or a quarter key such as Q3-2025.
  3. api.js serializes only non-default filters
    Any filter equal to 'all' is omitted from the query string rather than sent, so an unfiltered request is a bare URL. This is repeated inline in each method rather than factored into a helper.
  4. FastAPI filters the in-memory lists
    apply_filters() chains list comprehensions over warehouse, category and status (the latter two case-insensitively). filter_by_month() expands a quarter through QUARTER_MAP and substring-matches against order_date. Because the module globals are never copied, filtering is read-only by construction.
  5. Pydantic validates on the way out
    Endpoints declaring response_model coerce the raw dicts into InventoryItem, Order, DemandForecast or BacklogItem. Endpoints without one — the dashboard summary, all spending routes, both reports routes — return unvalidated dicts, so a JSON shape change there fails silently rather than loudly.
  6. Raw in refs, derived in computed
    Views store the response in a ref (allOrders, inventoryItems) and express every metric, grouping and chart series as a computed. Aggregation is therefore duplicated between client and server: the dashboard summary is computed in Python, while Spending and Demand recompute their totals in the browser.

Cross-cutting concerns

Internationalization

useI18n.js — hand-rolled, no i18n library. English and Japanese dictionaries in locales/, dot-path key lookup with English fallback, locale persisted to localStorage.

Currency

utils/currency.js derives currency from locale (en → USD, ja → JPY) and converts with a hardcoded USD_TO_JPY = 150 constant. Amounts are stored in USD server-side and converted at render time.

Identity

useAuth.js returns a mock user — no authentication of any kind. Profile fields and the task list are swapped based on the active locale.

Design system

Global styles live in App.vue. Slate palette, custom SVG charts rather than a charting library, CSS Grid layouts, no icon font or emoji in the UI.

Observations

Points where the current code diverges from what the architecture implies. These are descriptive, not prescriptive — several are deliberate for a workshop demo.

contract gap  Client calls endpoints the server doesn't expose

api.js defines six methods with no counterpart in main.py:

  • GET/POST/DELETE/PATCH /api/tasks — used by App.vue and TasksModal.vue
  • POST /api/purchase-orders and GET /api/purchase-orders/{backlogItemId}

Every one resolves to a 404. App.vue catches and logs the failure, so the task list silently falls back to the mock entries from useAuth. The backend does define a PurchaseOrder and CreatePurchaseOrderRequest model and loads an empty purchase_orders.json — the models and fixture exist, the write routes do not.

consistency  One view bypasses the API client

Reports.vue imports axios and hardcodes http://localhost:8001/api/reports/* at two call sites, while every other view goes through api.js. The base URL now exists in three places, so pointing the app at a non-local backend means editing more than one file.

by design  No persistence, no write path

All 14 endpoints are GET. mock_data.py reads the JSON files once at import and binds them to module globals; nothing writes back. Any state a user appears to change — completing a task, raising a purchase order — lives only in browser memory until reload.

deployment  Origin coupling

CORS is allow_origins=["*"] combined with allow_credentials=True, and Vite runs no dev proxy. The two servers must be reachable at exactly localhost:3000 and localhost:8001. A production build of the SPA would still call localhost:8001 from whatever host it is served on.

duplication  Aggregation on both sides

Quarterly and monthly rollups are computed in Python from orders; Spending and Dashboard recompute comparable totals in computed() properties over the same raw orders. The two paths can disagree without either being obviously wrong.

coverage  Backend tested, frontend not

40 pytest cases across inventory, dashboard and miscellaneous endpoints run against a TestClient fixture. There is no test runner, no test script, and no test files on the client side — the ~8,000 lines of Vue are unverified by automation.
